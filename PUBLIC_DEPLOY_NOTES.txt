Biohazard Outbreak — public WAN deploy
======================================

Set your real public IP in docker-compose.yml: `PUBLIC_IP` (with plain `docker run`, pass `-e PUBLIC_IP=...`).
Note: docker-compose.yml sets the value literally, so exporting PUBLIC_IP in your shell does not override it.

Examples in this file use 203.0.113.42 — that address is from RFC 5737 (TEST-NET-3), reserved for documentation only. It is not routable on the public Internet. Replace every example with your actual WAN IP.

Changes from upstream (corbin-zip/bioserver-docker)
--------------------------------------------------
- Dockerfile: FROM debian:bullseye-slim (not debian:latest) for PHP 7.4 + JDK 17 packages.
- Dockerfile: Apache/APR tarballs use archive.apache.org (dlcdn 404 for old versions).
- config/entrypoint.sh: PUBLIC_IP env for dnsmasq + bioserver configs.
- docker-compose.yml: MariaDB volume mysql_data; ports 53/udp, 80, 443, 8200/8300/8590/8690 TCP+UDP.
- Port 53: only UDP mapped (TCP/53 failed with "address in use" on some hosts; DNS over UDP is normal).

Router / firewall
-----------------
Forward to this machine’s LAN IP (same host running Docker):
- UDP 53 (DNS for PCSX2)
- TCP 80, 443
- TCP and UDP: 8200, 8300, 8590, 8690

Players (PCSX2 on Windows)
--------------------------
Set primary DNS to the same value as PUBLIC_IP (example only: 203.0.113.42). No hosts-file edits required if DNS works.

If your WAN IP changes
----------------------
Edit PUBLIC_IP in docker-compose.yml, then recreate the container:
  docker compose up -d --force-recreate
A plain restart is not enough: the first-run marker (/root/already-configured) lives inside the container, so only a new container re-applies PUBLIC_IP. The mysql_data volume is kept, and the SQL import uses IF NOT EXISTS, so re-running it on the existing database is harmless.

Verify from any PC (example — substitute your WAN IP)
-------------------------------------------------------
nslookup gate1.jp.dnas.playstation.org 203.0.113.42
If 203.0.113.42 were your real server, the answer should be that same address.
